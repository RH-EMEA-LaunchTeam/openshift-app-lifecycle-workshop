OpenShift Application Lifecycle Workshop

Session 2 turned the build of notes-app into a pipeline that clones, builds, scans and promotes only images without fixable critical CVEs. This session takes the same pipelines further:

  • Git triggers: pull requests build and scan, merges promote, without anyone running oc create.

  • Images you cannot rebuild, usually delivered by a vendor, go through an intake pipeline: inspect, scan, test under the platform’s default security, then approve, fix or reject.

  • Pipelines as a service: the platform team publishes the pipelines once, and every tenant reuses them.

On most platforms that host vendor software, the intake pipeline matters most. This session gives it the most time.

Used in Step 3
The platform setup is the same as for Session 2. To prepare your own cluster, run 20-session-prep/platform-setup.sh as cluster-admin, at least one hour before the session. Its header explains the arguments.

1. Complete the setup page

What: Follow Cluster Setup with your own user and namespace. For the optional Step 1, also set $GITHUB_FORK_URL and $PAC_WEBHOOK_URL.

Why: Every command in this session uses $NS, $GIT_REPO_URL and the lab context.

Verify: Context, namespace and tools 
oc whoami --context lab
oc get project "$NS" --context lab -o name
tkn version --component client
user1
project.project.openshift.io/app-lifecycle-user1
Client version: 0.46.2

Any recent tkn works.

2. Catch up to the end of Session 2

~3 minutes

What: If you are on a fresh cluster, run the catch-up script with the session number 3. It builds both images, deploys notes-app as at the end of Session 1, and adds the Session 2 pipeline objects: the pipeline-ws claim, the promote-image and acs-image-scan Tasks and version 2 of notes-app-build.

Why: Every step in this session starts from those objects. If you still have your namespace from Session 2 with Step 3 completed, skip the script and only check that $ROUTE is set.

./20-session-prep/catch-up.sh "$NS" lab 3

Then export the route and save it in myenv.sh:

export ROUTE=$(oc get route notes-app -n "$NS" --context lab -o jsonpath='{.spec.host}')
echo "export ROUTE=$ROUTE" >> myenv.sh
The script is safe to re-run, also on a namespace that already has the Session 2 objects.
Verify: The Session 2 pipeline and Tasks exist 
oc get pipeline notes-app-build -n "$NS" --context lab -o jsonpath='{.spec.tasks[*].name}{"\n"}'
oc get task,pvc -n "$NS" --context lab -o name
oc get istag notes-legacy:latest -n "$NS" --context lab -o name

Questions to prepare

  • Do vendors deliver source, Containerfiles, images or image archives? For how many of your applications each?

  • Who may accept a vulnerability risk for a vendor image, and for how long?

  • How many pipeline templates would cover most of your applications, and who maintains them?
