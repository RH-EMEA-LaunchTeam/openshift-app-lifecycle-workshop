= Session 3 - Vendor Images and Shared Pipelines: Intake, Git Triggers and Pipelines as a Service
include::_attributes.adoc[]

xref:20-build-pipelines.adoc[Session 2] turned the build of `notes-app` into a pipeline that clones, builds, scans and promotes only images without fixable critical CVEs. This session takes the same pipelines further:

* *Git triggers*: pull requests build and scan, merges promote, without anyone running `oc create`.
* *Images you cannot rebuild*, usually delivered by a vendor, go through an *intake* pipeline: inspect, scan, test under the platform's default security, then approve, fix or reject.
* *Pipelines as a service*: the platform team publishes the pipelines once, and every tenant reuses them.

On most platforms that host vendor software, the intake pipeline matters most. This session gives it the most time.

== Before you start

Like Session 2, this session runs on a cluster that several participants share. Each participant has their own user and their own namespace, with admin rights on that namespace only. The instructor has already done the platform-side setup.

[cols="2,4",options="header"]
|===
| Prepared by the platform team (instructor) | Why it is not part of your steps

| OpenShift Pipelines operator, with Pipelines as Code
| Cluster-wide component, installed once by the platform team

| ACS Central and SecuredCluster, plus an `acs-api` Secret in your namespace
| The security team owns the scanner and hands each tenant a token for its CI

| LimitRange and ResourceQuota on your namespace
| Platform guardrails from xref:14-health-and-resources.adoc#tenant-guardrails[Session 1, Step 4]

| `platform-pipelines` namespace with shared Tasks and Pipelines
| Used in xref:33-pipeline-service.adoc[Step 3]
|===

NOTE: The platform setup is the same as for Session 2. To prepare your own cluster, run `20-session-prep/platform-setup.sh` as cluster-admin, *at least one hour before the session*. Its header explains the arguments.

* How many pipeline templates would cover most of your applications, and who maintains them?
