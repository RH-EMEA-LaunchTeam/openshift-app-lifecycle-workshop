== Planned steps

. Pipelines as Code (optional): pull requests build and scan, merges promote, with results reported in GitHub
. Vendor image intake: an intake pipeline that inspects, scans and tests an image under restricted-v2, and four remediation levels for images that run as root
. Pipelines as a service (optional): the platform team publishes the pipelines once and every tenant reuses them

== What the session leaves behind

* An intake pipeline and a documented decision path for vendor images
* A shared pipeline catalogue that tenants reference instead of copying

== Questions to prepare

* Do vendors deliver source, Containerfiles, images or image archives? For how many of your applications each?
* Who may accept a vulnerability risk for a vendor image, and for how long?
* How many pipeline templates would cover most of your applications, and who maintains them?
